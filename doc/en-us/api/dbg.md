# Debug Tool API — `infinity_dbg.ps1`

`infinity_dbg.ps1` is the Infinity Build debugger for running build artifacts generated by `infinity_build.ps1` that contain debug information. When an error occurs, it maps line numbers from the merged script back to the original source file line numbers.

---

## Parameters

| Parameter | Type | Required | Description |
| - | - | - | - |
| `-ScriptPath` | `string` | Yes | Path to the script file to debug (i.e., the build artifact `.ps1` file) |

```powershell
.\infinity_dbg.ps1 -ScriptPath ".\build\output.ps1"
```

> Extra arguments passed to the debugged script are automatically forwarded:
> ```powershell
> .\infinity_dbg.ps1 -ScriptPath ".\build\output.ps1" -Mode "Production" -Verbose
> ```

---

## How It Works

### Debug Mapping File

The debugger relies on the `.debug.json` file generated during the build process. This file resides in the same directory as the build artifact, following the naming convention:

```
<script_name>.debug.json
```

For example, `output.ps1` corresponds to `output.debug.json`.

**Mapping file format**:

```json
[
    {
        "OutputLine": 15,
        "SourceFile": "C:\\project\\src\\core.ps1",
        "SourceLineNum": 42
    },
    {
        "OutputLine": 16,
        "SourceFile": "C:\\project\\src\\core.ps1",
        "SourceLineNum": 43
    }
]
```

- `OutputLine`: Line number in the merged output script
- `SourceFile`: Full path to the original source file
- `SourceLineNum`: Line number in the original source file

### Error Handling Flow

1. Execute the target script (via dot-source, running in the current scope)
2. If the script completes normally, the debugger reports "Execution complete"
3. If the script throws an exception:
   - Print the error message
   - Print the call stack trace
   - For each stack frame, attempt to map the output line number back to the source file line number
   - Print `-> at <source file>: line <source line>` mapping below the original stack info

### Without Debug Information

If the `.debug.json` file is not found or fails to parse, the debugger will still execute the script normally and catch errors, but will be unable to provide source file line number mapping. A warning will be issued.

## Integration with the Build Pipeline

```powershell
# Step 1: Build the project (generates output.ps1 + output.debug.json)
.\infinity_build.ps1 -ConfigPath ".\myproject.json"

# Step 2: Run with the debugger
.\infinity_dbg.ps1 -ScriptPath ".\build\output.ps1"

# Step 3: (Optional) Debug with arguments
.\infinity_dbg.ps1 -ScriptPath ".\build\output.ps1" --verbose --config "prod.json"
```

## Log Configuration

The debugger internally uses `infinity_log.ps1` with the log level fixed at `LogDebug` and the application name set to `InfinityDbg`. You can adjust the log verbosity via `$Script:DbgLoggerServer.LogLevel`:

```powershell
# Adjust before invoking the debugger (requires modifying the script or dot-sourcing)
$Script:DbgLoggerServer.LogLevel = [LogType]::LogInfo  # Show only info and errors
```

---

## Notes

1. **Dependency**: The debugger executes scripts via dot-sourcing (`.`), so variables and functions from the script persist in the current scope
2. **Mapping Precision**: Only lines parsed through `Get-InfinityModule` can be mapped. Pure comment lines, blank lines, and lines removed by `#infb: rm` do not exist in the output and cannot be mapped
3. **Nested Errors**: If the debugged script calls other scripts, errors from those external scripts cannot be mapped
4. **Performance**: The debugger runs scripts at normal speed with no additional performance overhead (only parses the stack on exceptions)
